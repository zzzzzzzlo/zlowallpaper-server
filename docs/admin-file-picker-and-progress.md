# 工作台文件选择与上传进度

2026-10-16。仅修改管理端界面和浏览器传输，不修改数据库或商品接口协议。

## 文件选择范围

原来“封面图片”“原文件”是关联原生文件输入的label，浏览器默认会在点击标题时打开文件选择器；原生输入中的文件名区域也能点击。此行为不属于按钮的视觉溢出，但与预期点击范围不符。

现在每个控件由普通文字标题、独立选择按钮、普通文件名文字和隐藏的文件输入组成。仅按钮调用对应input.click()；标题、文件名和状态文字不绑定选择动作。键盘Enter/空格仍可激活按钮，保存中按钮禁用。文件名限制在所在列宽度内，长名称省略，悬停显示完整名称。取消并重新打开弹窗会清空选择和文件名。

文件选择仍只在本地预览，点击创建/保存后才一次multipart提交，没有新增独立上传接口。

## 上传进度

创建和修改商品共用进度显示：

1. 浏览器发送multipart资料及文件，显示真实百分比和已发送/总字节数。
2. 请求体发送完毕后显示100%和“文件已上传，正在校验并保存…”。此时服务端可能仍在校验媒体、上传OSS和写数据库，不能提前显示创建成功。
3. 收到并校验成功响应后关闭弹窗并刷新列表；失败则显示真实错误，停止进度并保留所选文件。

进度代表浏览器到后端的请求体发送进度，不是后端到OSS的上传进度。模拟模式只显示“演示保存中（不上传真实文件）”，不编造百分比。

## 调用链与文件

```text
app.js表单submit
  → ApiClient.create / update(body, {onUploadProgress})
  → ApiClient.request：令牌、超时、取消和结果校验
  → uploadWithProgress：XMLHttpRequest发送FormData，报告upload.progress/load
  → Response交回ApiClient：沿用HTTP状态、错误码、requestId和商品结构校验
  → app.js更新进度、处理成功或失败
```

- public/index.html：独立选择按钮、文件名和progress元素。
- public/styles.css：按钮点击范围、受限文件名宽度与进度样式。
- public/js/app.js：文件选择显示、保存中禁用按钮、上传与服务端处理阶段。
- public/js/api.js：仅为multipart接入可选uploadTransport，其余请求仍使用原fetch传输。
- public/js/upload.js：XHR事件、统一AbortSignal取消、响应体4MiB限制。
- tests/upload.test.mjs：进度阶段、后端失败、取消不重放、响应大小和401失效测试。

普通fetch请求仍禁用重定向和Cookie；跨域上传XHR不启用凭证携带，并拒绝响应地址与请求地址不一致的结果。上传不手动设置Content-Type，由浏览器生成multipart boundary。

## 验证

- Node测试40项全部通过，Prettier检查通过。
- Playwright验证1440px和390px：标题/文件名/状态的点击触发数均为0；两个按钮分别触发自己的文件输入；键盘Enter可用；长文件名不撑宽页面或弹窗。
- 浏览器使用独立HTTP测试夹具与限速真实XHR传输，观察2%至100%的上传事件、100%等待后端处理及成功关闭弹窗。
- 模拟后端422失败，确认错误码保留、进度停止、所选文件仍在。
- 本机真实后端只读OPTIONS预检通过，允许工作台来源上传；验收未创建真实商品或上传OSS。

工作台完成当前编辑后刷新页面即可载入新代码，不需要重启后端。
