## 一、页面和操作

- 增加“商品管理 / 分类管理”入口，复用现有工作台导航方式。
- 分类列表显示名称、排序值、启用/停用状态、关联商品数和操作。排序值越小越靠前，相同排序值按 ID 升序排列。
- 支持新增分类、编辑名称和排序、启用/停用、删除分类。名称去掉首尾空格后不能为空，最长 64 个 Unicode 字符；名称不可重复，后端判断为准。
- 新增时排序值默认 0，状态默认启用。排序值使用 JSON 整数，范围为 -2147483648 至 2147483647；状态使用 JSON 布尔值，不发送 0/1。
- 删除前二次确认，明确只删除分类，不能连带删除商品、文件、订单或购买权益。
- 有任何商品引用的分类不得删除，包括草稿、已上架和已下架商品。关联商品数大于 0 时显示原因并阻止删除，提示先在商品编辑中迁移分类，或选择停用。
- 列表中的关联商品数只是展示时的快照。即使展示为 0，服务器仍可能返回 409 CATEGORY_IN_USE，前端必须显示原因并刷新分类列表。
- 停用与删除分开操作，不得自动将删除失败转换成停用。

## 二、分类业务规则

- 停用只表示不再出现在公开分类列表和新增商品的分类选项里；不会自动下架或删除已有商品。已有商品仍保留原 categoryId/categoryName，并按原商品发布规则展示。
- 商品编辑器使用公开 `GET /categories` 获取启用分类选项。编辑已有商品时，如果原分类已停用，仍显示原分类名称并标注“已停用”；未修改分类时不要发送 categoryId，不得偷偷换成第一个启用分类。
- 允许已有商品保留原停用分类，但新建商品、将商品换到另一个分类时，只能选择启用分类。后端负责最终校验。
- 分类新增、改名、启停或删除成功后，刷新管理列表和商品编辑器的分类选项；不会自动更新另一台设备上的商城，商城重新请求时读取最新结果。

## 三、新增接口契约

基础地址仍为 `http://127.0.0.1:8080/api/v1`。所有下列 `/admin/` 接口要求 `Authorization: Bearer <accessToken>`，并由后端检查管理员权限。

| 方法 / 相对路径 | 请求 | 成功 HTTP | 响应 data |
| --- | --- | --- | --- |
| GET `/admin/categories` | 无业务参数，首期返回完整列表，不分页 | 200 | `AdminCategory[]`，含启用和停用分类 |
| POST `/admin/categories` | 必填 name；可选 sortOrder、enabled | 201 | 新建的 `AdminCategory` |
| PATCH `/admin/categories/{id}` | name、sortOrder、enabled 中至少一个字段，只发送实际变化项 | 200 | 修改后的 `AdminCategory` |
| DELETE `/admin/categories/{id}` | 无请求体；只允许删除未被任何商品引用的分类 | 200 | `{}` |

`AdminCategory` 的必填字段：

```json
{
  "id": "1",
  "name": "风景",
  "sortOrder": 0,
  "enabled": true,
  "wallpaperCount": 3
}
```

- id 是字符串，由服务器生成；不能由创建或编辑请求指定。
- name 是字符串；服务器去掉首尾空格后校验非空和长度。数据库名称比较不区分大小写，是否重复由服务器最终决定，包括停用分类的名称。
- sortOrder 是上述范围内的整数；enabled 是布尔值。
- wallpaperCount 是非负整数，计算所有商品状态的引用总数，由服务器生成；不存进 categories 表，也不能由客户端写入。
- POST 省略 sortOrder/ enabled 时，后端默认 0/ true；PATCH 省略的字段保持原值，不接受未定义字段。
- 返回继续使用统一 JSON 外壳：`{code:"OK",message:"",data:...,requestId:"..."}`，包括 DELETE 成功；不要用 HTTP 204 搭配 JSON 响应体。

保留现有公开 `GET /categories`：无需登录，只返回启用分类，data 仍为仅含 id/name 的数组。不要给公开 Category 强行添加管理员字段，也不要用公开接口替代管理列表。

错误响应沿用统一结构，保留真实 HTTP 状态，data 为 null：

| HTTP | code | 含义 |
| --- | --- | --- |
| 400 | VALIDATION_ERROR | 字段、类型、长度或请求内容不符合约定 |
| 401 | SESSION_EXPIRED | 会话失效，按现有机制刷新或重新登录 |
| 403 | FORBIDDEN | 当前账号不是管理员或权限被撤销 |
| 404 | CATEGORY_NOT_FOUND | 目标分类不存在；再次删除已删除分类也返回此错误 |
| 409 | CATEGORY_NAME_EXISTS | 分类名称重复 |
| 409 | CATEGORY_IN_USE | 分类仍被商品引用，无法删除 |

网络、超时、500/503 等故障沿用现有处理。写请求不得自动重放；失败或超时不得显示保存/删除成功，真实模式不得回退成模拟数据。后端应保留外键约束处理并发引用，前端的计数不能作为删除授权依据。
