# 当前前后端接口适配情况

更新：2026-10-16。此次已经同步两个前端的实际代码，并更新桌面运行目录；不再只是同步OpenAPI。源码在`D:\Codex\software\zlowallpaper`，用户实际使用的客户端在`E:\zlowallpaper`。

## 已统一

| 功能 | 当前结果 |
| --- | --- |
| 管理端商品目录/创建/编辑/上下架 | ZLC商品校验通过，不再限定CNY；继续使用已有multipart及当前文件协议 |
| 价格单位 | 两端新商品均显示壁纸币，100整数单位=1币；历史CNY订单仍按原币种显示 |
| 正常付款 | 桌面使用POST /orders/{id}/pay，PENDING订单显示付款按钮，不依赖已移除testPaymentEnabled |
| 余额 | 桌面个人信息页展示balanceCents；打开/手动刷新时GET /me，付款成功或余额不足后也刷新 |
| 个人信息 | 登录后账号旁新增按钮，显示ID、用户名及余额；本次只读取，不伪造修改资料接口 |
| 已购停售商品详情 | 直接使用GET /me/wallpapers返回的完整资料，不再请求只允许上架商品的公开详情 |
| 已购封面 | 仅向当前API同源/me/wallpapers/{id}/cover附加Bearer；公开封面和外部存储不转发账号凭证 |
| 封面刷新 | 列表刷新、已购同步及账号切换时清理缓存并取消旧读取，旧响应不能覆盖新图 |
| 上传图片后缀错误 | 工作台读文件头，识别真实JPEG/PNG等格式，必要时修正上传File名称；不转码、不改磁盘原文件 |
| 模拟与测试 | 使用ZLC、balanceCents及正常扣币行为；新注册演示用户余额0，专用demo账号演示余额100币 |
| 订单/已购/下载 | 路径、包装、字符串ID及文件SHA协议对应；下载直接访问OSS，不携带账号Bearer |

公开列表、公开详情、公开封面仍只展示上架商品；已购入口按当前账号权益限制。没有恢复独立上传、assets表或商品历史版本。

## 真实验证

1. Playwright连接真实本机后端：商品目录正常，用户提供的围巾图片一次提交创建成功，HTTP 201，实际格式JPEG，2358×1498。
2. 文件选择阶段无上传请求；保存时仅一次multipart提交。
3. Qt连接真实后端：测试余额100→88币，重复付款不重复扣币；停售后继续获得下载授权并下载入库，SHA一致。
4. Qt个人信息页显示真实88.00币；已购封面鉴权、列表刷新重新取图及无旧测试开关时付款按钮均有回归。
5. 管理端35项、Qt17项全部通过；Qt包含真实后端/OSS闭环。临时账号、订单、权益、商品及两个新OSS对象均已清理，不改用户原有密码、角色、余额或文件。
